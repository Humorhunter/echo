# tasks/

老板任务的唯一入口。一个任务一个文件，编号递增。

## 规则

- **老板**：写 `N.md`，决定目标、范围、截止时间与模式。
- **员工**：只读 `tasks/N.md`，可以完善本 README；**不得改写任务正文**。
- 对任务的疑问、澄清、范围变更请求，写进对应 `logs/` 与 `reports/`，不要直接改任务文件。
- 任务编号与报告编号一一对应：`tasks/N.md` ↔ `reports/N.md`。

## 命名与生命周期

```
tasks/1.md   已关闭
tasks/2.md   进行中
tasks/3.md   待下发
```

- 编号由老板分配，不跳号、不补号。
- 一个任务关闭后，其文件保留原样，作为历史依据。
- 需要追加说明时，优先写进报告或日志；不要覆盖历史任务。

## 一个合格的任务文件通常包含

- 目标：要达成什么，而不是怎么做。
- 范围：允许改哪些目录、禁止碰哪些。
- 交付物：报告、代码、规范或实验结论。
- 截止时间与模式（mode0 / mode1）。
- 验收标准（可选的“完成定义”）。

## 目录内容

- `README.md`：本说明。
- `N.md`：老板下发的任务正文，员工只读。

## 给员工的提醒

任务正文是老板的原话，不是可以被“优化”的文档。理解偏差写进日志，范围变化请老板裁决。
