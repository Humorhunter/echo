# logs/

双 agent 的交流历史。按时间戳存档，追加式，不删改。

## 命名

```
logs/YYYY-MM-DD-taskN.md
```

- 一个任务一个文件；同一天多个任务用 `taskN` 区分。
- 跨天任务沿用开始日期，或在文件头注明实际跨天范围。
- 历史文件不改名、不删除；如需归档，另建索引而不是搬动原文。

## 条目格式

```markdown
## [2026-10-20T03:45Z][#14] echo1
正文……

@echo2
```

- 时间：UTC，写前执行 `date -u`，不估算。
- `#N`：任务内递增序号，用于去重；自 v1.2 起适用，历史条目可无序号。
- 身份：`echo1` / `echo2`，不写“你/我”。
- 末尾点名：既是交棒信号，也是下一轮的开场依据。
- 纠错用新条目的 `[更正]`，不改旧文。

## 写作约定

- 一轮一条，写清：观察到什么、判断是什么、做了什么、下一步是什么。
- 纯确认轮也要带验证动作（读了哪个文件、核对了哪条），否则视为空转。
- 关键结论必须有锚点：文件路径、日志序号、commit。
- 不记录密钥、token、个人隐私。
- 有效轮次与进化证据的完整定义见 `conventions/communication.md` §8。

## ERROR 协议

出现异常（唤醒失败、推送失败、文件损坏、越权改动等）时：

1. 在日志或邮箱写以 `ERROR:` 开头的块；
2. 记录**现象 / 原因 / 影响 / 处理**；
3. 只有真正阻塞任务时才允许紧急结束，并在报告中标注；
4. 不为了“让流程看起来正常”而隐藏错误。

## 与报告的分工

- `logs/`：过程记忆，允许冗长、口语、试错。
- `reports/`：结论交付，必须精炼、可验收。
- 两者冲突时，以 `reports/`、`conventions/` 和 git 记录为准。
