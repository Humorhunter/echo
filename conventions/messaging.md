# 邮箱通信规范 v1.1

`logs/` 是事实来源；邮箱是**传输层**，只负责把需要行动的消息可靠地送到对方手里。

> 2026-10-20 task3 老板决定：**默认采用**。默认指“需要行动/回执的消息默认走邮箱”，不指“所有交流都双写”。

工具：`scripts/msg.py`（一消息一文件，`tmp/mailbox/<agent>/`，`tmp/` 不入 git）。

## 1. 什么时候用邮箱（默认采用）

**默认用**：

- `ASK`：需要对方做决定、复核、执行，且期待明确回执；
- `ACK`：对某个 `ASK` 的完成回执（`reply_to` 指向原消息）；
- `ERROR`：需要对方立即知道的异常；
- 需要唤醒对方但正文较长的场景（正文仍落日志，邮箱只放摘要 + 日志锚点）。

**默认不用**：

- 日常 `INFO`、背景说明、长推理——只写日志；
- 已经写在日志里的完整内容——邮箱不要整段复制；
- 密钥、token、隐私数据——任何通道都不放。

原则：**需要回执的默认走邮箱，只需要阅读的走日志。** 避免同一内容双写；邮箱正文只放摘要/请求，完整论证落日志。

## 2. 消息格式

```json
{
  "id": "<time_ns>-<pid>-<rand6>",
  "ts": "2026-10-20T05:00:00Z",
  "from": "echo1",
  "to": "echo2",
  "type": "ASK",
  "reply_to": "179247...-...-...",
  "body": "自然语言正文；需要时引用 logs/2026-10-20-task2.md [#8]"
}
```

- `body` 一律自然语言；结构化只用于路由。
- `reply_to` 只指向真正回复的那条消息。
- 重要结论必须在日志里有对应条目或引用；邮箱消息不能成为唯一证据。
- 不发明紧凑 DSL；外部研究（见 `docs/agent-communication.md`）显示自然语言正文更可靠。

## 3. 生命周期

1. **send**：写临时文件 + fsync，再 `rename` 发布；读方只会看到完整消息。
2. **wake**：用 tmux `send-keys` 发一行提醒（只写“请读 logs/... 末尾并 poll <agent>”，不复述正文）。
3. **poll / read**：按 `id` 排序读取；`wait` 可轮询等待。
4. **act**：完成消息要求的工作。
5. **ack**：移入 `done/`。`ack` 表示“已处理”，不表示“已读”。
6. 需要回执的 `ASK`，用 `ACK` 消息回复并 `reply_to` 原 id。

## 4. 去重与失败

- `id` 唯一；同一条消息重复投递时只处理一次，多余的直接 `ack`。
- 唤醒失败不等于消息丢失：消息仍在邮箱，重新 `poll` 即可。
- `ack` 失败（不存在 / 已办 / 非法 id）按工具输出处理，不手改目录。
- 出现异常按 `conventions/communication.md` §9 写 `ERROR:` 块。
- `tmp/mailbox/` 可随时清理；需要长期保留的内容必须进日志或报告。

## 5. 采用边界（task3 起默认）

- 邮箱是**默认传输层**：`ASK`/`ACK`/`ERROR` 以及需要对方行动的消息默认走邮箱；`INFO`/长文/背景仍只写日志。
- 适用条件：消息需要明确回执、跨会话唤醒不可靠、或同一轮有多个并行请求。
- 不适用：长文讨论、需要完整上下文的决策、只需 FYI 的信息。
- 账号/密钥/隐私数据任何通道都不放。
- 默认不等于双写：邮箱只放“要做什么 + 日志锚点”，完整内容在日志。
- 20 消息对照实验用于测量 token/还原率/可读性，结果只用于调优，不改变“默认采用”这一决定；除非出现净负面证据并由老板改判。

## 6. 观测指标

- 发出的 `ASK` 数、被 `ack` 的比例；
- 从 send 到 ack 的中位时间（人工记录即可）；
- 重复处理 / 丢失 / 误唤醒次数；
- 与“只用日志 + tmux”相比，是否减少了重读全文和歧义。

## 7. 默认采用后的最小纪律

1. 每条 `ASK` 必须有日志锚点（`logs/... [#N]` 或报告路径），邮箱不得成为唯一证据。
2. `ack` 表示“已处理”，不表示“已读”；需要回执的 `ASK` 必须回 `ACK` 并 `reply_to`。
3. 同一内容不双写；邮箱正文 ≤ 日志对应段的摘要，详细论证在日志。
4. 每天收工前 `status` 清零未读；`tmp/mailbox/` 可清理，长期内容进日志/报告。
5. 唤醒消息只写“请读 logs/... 末尾并 poll <agent>”，不复述正文。
