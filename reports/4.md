## 二、Q2：选 **#1 Agent 能力防火墙 / IAM**，工作名 **Scoped**

### 2.1 是什么

**Scoped 是 agent 与工具之间的权限层**：声明它能在哪个会话、对哪个工具/资源做哪个动作；高危动作默认**问你一句**；每次决策留一张可回放的**收据**。

```bash
scoped init                 # 生成 scoped.yaml + .scoped/
scoped run -- claude        # 用策略包住 agent；正常命令不变
scoped audit verify         # 校验审计链/收据未被篡改
```

策略可提交进 repo：Postgres 只读、禁 `.env`/`rm -rf`、shell allowlist、HTTP 域名 allowlist、高危动作审批 10 分钟。
它**不是**网络安全产品，更像 **agent 的 `chmod`/IAM**——开发者工具，不是渗透测试。
**先把话说直**：是，#1/#2 都沾“AI 安全”；但 #1 离安全研究最远、离开发者日常最近。老板不需要懂攻防，只需要判断一件事：**用 coding agent 的人，怕不怕它下一秒删库/泄密/误推 main？** 怕，就愿意装一个“刹车 + 收据”。我们卖的不是安全，是“敢把 agent 放出去”的底气。

### 2.2 目标与用户

- **目标**：让“给 agent 上权限”像写 `Dockerfile` 一样简单；默认 ASK，按需授权；正常开发不碍事；出事能证明。
- **v0.1（2 周）**：包住 Claude Code；三类策略；5 个攻击 fixtures 全拦；收据可回放；<10% 延迟。
- **v1.0（3 个月）**：3 个 harness、策略模板库、审批 CLI、审计导出；目标 5k star / 50 个真实团队。
- **用户**：① 用 coding agent 的开发者（怕 `rm -rf`/`.env`/误推 main）；② 平台/DevOps（多 agent、多 MCP、要审计）；③ 合规团队（次要）。

### 2.3 为什么是 #1，不是 #2

- **责任边界**：#2 要托管/扫描/背书别人的 skill，出了恶意包要承担运营与声誉责任；#1 只在本机拦工具调用，不分发内容，责任清晰得多。老板担心的“负不起责”，直接指向 #1。
- **钩子更强**：同一句 prompt，无策略时 `DROP TABLE` 成功；有策略时被拦 + 审批 + 收据。30 秒 GIF 讲清。
- **竞争空位更大**：`agent firewall` 仅 14 个 >100★（Top 1,616★）；#2 已有 ClawHub 9.5k、SkillHub 5.3k、Microsoft apm 4k。
- **不绑平台**：#1 跨 Claude Code/Codex/OpenCode；#2 容易被平台 registry 吸走。

### 2.4 竞品：不吹“首个”，只讲差异

echo2 实查后修正：赛道**不是“开源无头部”**，已有 5+ 同构先行者——`agentperms`（PyPI，MIT，stdio 代理 + 最小权限自动推导）、`agent-policy-gateway`（PyPI 0.2.0，YAML + 污点追踪 + 审计）、AgentGate×2 / Agent-IAM；商业侧有 AgentPermit/Pillar/Koi/Defender。
**我们的差异收束为三点**：① **可回放收据**（每次 allow/deny/ask 带策略命中、证据、审批人、前后状态、hash，可离线复验——竞品只做拦截/日志）；② **跨 harness + 政策可携**（Claude Code/Codex/OpenCode，策略文件跟 repo 走）；③ **本地、无账号、无托管内容**。
“能拦”不是差异，平台原生 hook 已能拦；差异在“跨平台 + 可证明 + 可携带”。

### 2.5 能不能确保获得关注？不能保证，但可以显著提高概率

**诚实回答**：没有项目能“确保”star。我的主观估计（无公开基准可依，仅为经验先验）：如果首发命中，30 天 1k star 约 30–50%，90 天 5k 约 10–20%；如果只靠发 repo 不做事，低于 10%。我们按“提高概率”而不是“保证”来做：

1. **30 秒钩子**：“我给 Claude Code 开了 10 分钟 root，Scoped 拦下 7 个会毁掉机器/仓库/云账号的动作。”无策略 vs 有策略 + 收据回放。
2. **原创数据**：扫描 100 个热门 MCP server，发布《MCP Permission Report》（申请了什么 vs 实际需要什么）；这是可引用的首发弹药。
3. **分发**：Show HN / Reddit（r/ClaudeAI、r/LocalLLaMA、r/programming、r/devops）/ X / MCP 目录 / awesome 列表；首发支持 3 个 harness；一条命令安装。
4. **Design partners：目标 20 家，发布时至少 5 个可验证证言**：Week 2 先访谈 5 家，收集“拦对了/误拦了”的真实案例；20 家是持续目标，不写成首发前必须完成。
5. **策略模板库**：Postgres 只读、AWS 只读、repo 安全、CI 模式；复制即用。
6. **止损**：30 天 <300 star 或 <5 个真实团队 → 缩窄到“Postgres MCP 只读 guard”/“Claude Code 权限管理器”再发；平台原生覆盖 → 转做跨平台策略/审计层。
7. **Kill 条件（Week 1）**：Claude Code 上做不到“一行配置 + 拦截 Replit 式事故（教育性复刻，标注来源）+ 收据回放”三连 demo → 转 #2 或重估。

**可能杀死它的东西**：平台原生权限、误报/漏报、配置负担、责任反噬。对策：跨 harness、默认模板、默认 ASK 而不是 hard-deny、明确 advisory 定位。

### 2.6 责任边界（老板最担心的）

- **Apache-2.0 + NOTICE**：`not audited for hostile environments`，不提供担保。
- **本地优先**：默认不联网、不上传 prompt/代码/trace；不运营托管服务；不托管第三方内容。
- **定位**：**advisory guardrail，不是 sandbox，也不是安全保证**；README 第一屏写清绕过风险。
- **默认 ASK**：高危动作给“批准一次/10 分钟/本会话”三档，降低错杀与“出事找我们”的责任。
- **不做认证**：不声称 SOC2/ISO/EU AI Act 合规；只提供本地可验证记录。
- **不发布官方危险黑名单**：谁定黑名单谁担责；改社区 PR 政策模板。
- **不碰凭据**：不存密钥；审计默认只存 hash/摘要；SECURITY.md + 90 天披露。
- **不用老板个人品牌**：以 Scoped/贡献者身份发布，老板可匿名；需要时再决定是否露出。项目不靠个人 IP，靠可复现 demo 与数据。

这套边界不能消除所有法律风险（开源安全工具都有），但比“做 registry 托管别人的 skill”清晰得多。

## 三、Q3：多智能体对话到底有没有用？我们的真实想法

**有用，但不是因为“两个”。**

- **有用的**：并行调研（我定量/echo2 定性）确实快；独立复核抓到真问题——echo2 抓到我错标 1,184/26.1% 的出处，也推翻了我对 #8“格式不兼容”的假设；日志 + 邮箱 + 单写窗口让交接可追溯。这些是实打实的。
- **没用的**：开销大（邮箱 +34% 字节）、等待多、部分轮次是礼貌确认；两个 agent 虽然跑在不同模型上（echo1 DeepSeek / echo2 GLM），但共享同一任务框架、同一批资料和同一套提示结构，错误仍可能相关，容易“互相点头”；“不同模型”不等于独立验证。**真正起作用的是“先调研证据、再对话”和“协议强制证据与共识分离”，不是对话本身产生证据。** echo2 还指出：协议有效的前提是“共享工作区 + 互不信任写权”，泛化到任意一对 agent 时前提会消失，所以“一键 agent-pair 模板”的可移植性没那么高。
- **对纯编码实现**：单 agent + 测试大概率更快；双 agent 适合调研/设计/复核/留痕，不适合快改小 bug。

**包装/benchmark 有必要吗？有，但做配角，不做主线。**
- 不建议做“多 agent 一键框架”大而全产品；用户不为“两个 agent”买单，**也不建议现在做“一键接口”**——先把 Scoped 做出来，协议模板作为开源小工具/附录，不抢主线。
- 建议 Scoped 立项后做一个**小而诚实**的 companion：10–20 个 coding 任务，A 臂单 agent、B 臂“实现 + 只做复核/反方”，**先钉难度分层与成本口径**（否则容易得出“双 agent 无用”的假阴）；测正确率、成本、时间、人类可读性。把协议（logs/邮箱/单写窗口/复核清单）开源成 `agent-pair` 模板。
- 故事应该是“**我们如何用两个 agent + 可审计协议做出 Scoped**”，不是“多 agent 更强”。它给 Scoped 发布做背书，也回答老板“这个协作模式有没有推广价值”——有，但价值在协议/工件，不在“两个”。
