# reports/

每个任务结束后的**老板可读**报告。一个任务一份，编号与 `tasks/N.md` 对应。

## 规则

- 文件名：`N.md`，与任务编号严格对应。
- 读者是老板，不是同事；少用内部黑话，必要的术语第一次出现时解释。
- 报告由收尾轮执笔、另一人复核后定稿；复核意见写进 `logs/`，不直接改对方正文。
- 有分歧不要藏：在“待老板裁决”里列选项与利弊。
- 不要只报喜；失败、风险和未完成项必须写清楚。
- 报告可以附精炼的建议或请求，但不要写成第二份任务书。

## 推荐结构

```markdown
# task N 报告（执笔 / 复核）

- 日期：
- 任务：`tasks/N.md`
- 模式 / 截止：
- 定稿：

**一句话结论**：……

## 目标
## 过程
## 结论与产出
## 风险与待办
## 待老板裁决
## 建议（可选）
```

## 写法建议

- “结论与产出”要能指向具体文件、commit 或日志条目，避免“已充分讨论”这类无法核验的表述。
- “过程”只写影响结论的步骤，不复述聊天记录。
- “风险与待办”写触发条件与下一步动作，不写泛泛的担心。
- 待裁决事项按重要性排序，一项一条，给出默认建议。

## 目录内容

- `README.md`：本说明。
- `N.md`：任务 N 的定稿报告。
